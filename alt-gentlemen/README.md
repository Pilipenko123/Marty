# 🎩 Alt-Джентельмены

Приватный мессенджер для своих в стиле Bitrix24: **любой участник создаёт свои групповые чаты**
и пишет личные сообщения один на один. Комментарии внутри сообщения, ответы-ссылки на любое
сообщение чата, статусы «в сети» и «прочитано», счётчики непрочитанного, обращения через `@`,
круглые аватары, поиск по всем чатам, шкала памяти и архивы, которые каждый может сохранить себе.
Регистрация прямо в браузере (ПК и телефон), всё шифруется сквозным шифрованием.

Жить мессенджер умеет в двух местах — переписка, внешний вид и все возможности одинаковые:

| | На своём компьютере | В облаке Yandex Cloud |
|---|---|---|
| Что нужно | установленный Node.js | аккаунт в Yandex Cloud |
| Доступен друзьям | пока компьютер включён | круглосуточно |
| Где лежит переписка | папка `data` рядом с программой | бессерверная база Yandex Database |
| Цена | электричество | 0 ₽ в пределах бесплатного лимита |
| Как запустить | [раздел 1](#1-как-запустить-на-своём-компьютере-5-минут) | [раздел 2](#2-как-поселить-мессенджер-в-облаке-yandex-cloud) |

Переехать из одного в другое можно в любой момент — это разные способы хранения, а программа одна.

## 1. Как запустить на своём компьютере (5 минут)

### Шаг 1. Установите Node.js
Скачайте LTS-версию с [nodejs.org](https://nodejs.org) и установите (Windows / macOS / Linux).
Проверка — в терминале (Windows: «Командная строка» или PowerShell):

```bash
node -v
```
Должна появиться версия, например `v22.x`. Нужна версия **18 или новее**.

### Шаг 2. Запустите чат
В терминале перейдите в папку с чатом и запустите сервер:

```bash
cd путь/к/репозиторию/alt-gentlemen
node server.js
```

Увидите:

```
  ╔══════════════════════════════════════════════╗
  ║           A L T - Д Ж Е Н Т Е Л Ь М Е Н Ы    ║
  ╚══════════════════════════════════════════════╝

  Мессенджер запущен. Открывайте в браузере:
    • на этом компьютере: http://localhost:8080
    • в этой Wi-Fi сети:  http://192.168.x.x:8080
```

> Никаких `npm install` не нужно — внешних библиотек нет.

### Шаг 3. Создайте мессенджер (только один раз)
Откройте **http://localhost:8080**. При первом запуске появится экран «Создать мессенджер»:

1. **Ваше имя** и **ваш пароль** — вы становитесь администратором.
2. **Кодовая фраза** — общий «ключ от двери». Её придумываете вы и передаёте друзьям
   (лично, голосом, в другом мессенджере). Без неё в мессенджере не зарегистрироваться.

Готово. Внутри пока пусто: нажмите **«＋ Новый чат»**, придумайте название и отметьте, кого позвать,
либо напишите кому-нибудь лично из списка слева. Мессенджер работает, пока запущен
`node server.js`. Остановить — `Ctrl + C` в терминале.

### Шаг 4. Пригласите друзей
Друг открывает адрес → вкладка **«Регистрация»** → вводит:
кодовую фразу (от вас) + своё имя + свой личный пароль. Всё, он внутри.
У каждого — **свой** пароль; кодовая фраза нужна только для первого входа с устройства.
Дальше любой может создавать групповые чаты и звать в них кого угодно из списка участников.

## 2. Как поселить мессенджер в облаке Yandex Cloud

Компьютер выключать можно — мессенджер будет работать сам. Программа и переписка переезжают
в два бесплатных сервиса: **Cloud Functions** (запускает код, когда кто-то открыл чат)
и **Yandex Database** (хранит зашифрованную переписку).

### Сколько это стоит

Каждый месяц Yandex Cloud не берёт денег за первые:

| Услуга | Бесплатно в месяц | Сколько тратит компания друзей |
|---|---|---|
| Вызовы функции | 1 000 000 | ~200 000 при ежедневном общении впятером |
| Время работы функции | 10 ГБ×час | около 1 ГБ×часа |
| Запросы к базе | 1 000 000 | ~500 000 |
| Хранение в базе | 1 ГБ | лимит чата по умолчанию 25 МБ |

Чтобы уложиться, мессенджер сделан экономным: страница спрашивает сервер о новостях
раз в 2,5 секунды, пока вы что-то делаете, реже — если вкладка просто открыта, и почти
не беспокоит его, когда она свёрнута. Один такой холостой вопрос — это **одно** обращение
к базе. Аватары скачиваются один раз и потом берутся из памяти браузера.

Если лимит всё же кончится, цена смешная: около 15–30 ₽ за лишний миллион вызовов.
Расход видно в консоли облака: **Биллинг → Детализация**.

> Для регистрации в Yandex Cloud понадобится привязать карту — это правило площадки,
> но в пределах бесплатных лимитов списаний не будет. Если платёжный аккаунт не нужен
> принципиально, остаются варианты из [раздела 7](#7-чтобы-мессенджер-работал-постоянно).

### Способ А. Одна команда в Cloud Shell (рекомендую)

**Cloud Shell** — это терминал прямо в браузере внутри консоли облака. Там уже стоят все
нужные инструменты, на свой компьютер ставить ничего не надо.

1. Заведите аккаунт на [cloud.yandex.ru](https://cloud.yandex.ru) и создайте платёжный аккаунт.
2. В консоли облака нажмите кнопку **Cloud Shell** (значок терминала сверху справа).
3. Вставьте в него три строки:

```bash
git clone https://github.com/Pilipenko123/Marty.git
cd Marty/alt-gentlemen
./cloud/deploy.sh
```

Скрипт сам создаст базу, служебную учётную запись, выдаст ей права, соберёт архив,
выложит функцию и откроет к ней доступ. В конце напечатает адрес:

```
      https://functions.yandexcloud.net/d4e********************
```

Это и есть ваш мессенджер. Откройте адрес — увидите знакомый экран «Создать мессенджер»:
имя, пароль, кодовая фраза. Дальше всё как обычно: рассылаете друзьям адрес и кодовую фразу.

Сохраните адрес в закладки — он больше не изменится.

### Способ Б. Руками через консоль облака

Если хочется всё видеть глазами:

1. **База.** Yandex Database → «Создать базу данных» → режим **Serverless**, имя `alt-gentlemen-db`.
   Откройте её и скопируйте строку **Document API эндпоинт**.
2. **Учётная запись.** Сервисные аккаунты → «Создать» → имя `alt-gentlemen-sa`,
   роль **`ydb.editor`** на каталог.
3. **Архив.** Соберите zip из файлов `index.js`, `package.json`, папок `cloud`, `lib`, `public`
   (всего около 60 КБ).
4. **Функция.** Cloud Functions → «Создать функцию» → имя `alt-gentlemen` → «Создать версию»:
   * среда выполнения — **Node.js 18**;
   * способ — «ZIP-архив», загрузите свой файл;
   * точка входа — **`index.handler`**;
   * таймаут — 30 секунд, память — 256 МБ;
   * сервисный аккаунт — `alt-gentlemen-sa`;
   * переменная окружения **`YDB_ENDPOINT`** — тот самый адрес Document API.
5. На вкладке «Обзор» включите **«Публичная функция»** и скопируйте ссылку для вызова.

### Обновить мессенджер

Повторите `./cloud/deploy.sh` — он выложит новую версию. **Переписка при этом не трогается**:
она лежит в базе отдельно от программы.

### Что меняется по сравнению с домашним запуском

* **Первое открытие после долгого затишья занимает секунду-полторы** — облако «будит» функцию.
  Дальше всё летает.
* Картинка в сообщении — до ~1,8 МБ (ограничение облака на размер запроса). Фотографии
  мессенджер и так сжимает сам, так что вы этого не заметите.
* Архивы чатов хранятся не в папке, а в той же базе; скачиваются так же — кнопкой.
* Резервная копия: кнопка **«Архивы»** → «Выгрузить всё» сохраняет вашу зашифрованную переписку
  файлом на компьютер. Можно и подключиться к облачной базе с домашнего компьютера:

```bash
STORE=ydb \
YDB_ENDPOINT=https://docapi.serverless.yandexcloud.net/ru-central1/... \
YDB_ACCESS_KEY_ID=... YDB_SECRET_ACCESS_KEY=... \
node server.js
```

(ключи создаются в сервисном аккаунте: «Создать статический ключ доступа»).

* Красивый адрес вместо длинного — по желанию, см. `cloud/api-gateway.yaml`.
  Учтите: у API-шлюза бесплатны только первые 100 000 запросов в месяц против миллиона у функции.

### Приватность в облаке

Облако видит **только шифротекст**. Тексты сообщений, названия чатов, вложения и аватары
шифруются в браузере, ключи не покидают устройства участников. В базе лежат строки вида
`"v2:9Kx1…"` — ни Яндекс, ни человек с доступом к консоли не прочитает ни переписку,
ни даже название чата. Видно только служебное: сколько участников, когда были сообщения, их размер.

## 3. Как открыть чат с телефона

Если мессенджер живёт в облаке — просто откройте его адрес, он уже по `https`. Ниже —
про домашний запуск.

**Вариант А — тот же Wi-Fi (быстро).**
Браузеры разрешают шифрование только на `https://` или на `localhost`, поэтому для телефона
запустите сервер с HTTPS (нужен `openssl`, он есть в macOS/Linux, в Windows — в составе Git):

```bash
HTTPS=1 node server.js            # macOS / Linux
set HTTPS=1 && node server.js     # Windows CMD
$env:HTTPS=1; node server.js      # Windows PowerShell
```

Затем на телефоне откройте `https://192.168.x.x:8080` (адрес показан при запуске) и один раз
подтвердите «Всё равно перейти» — сертификат самоподписанный, соединение при этом шифруется.

**Вариант Б — доступ из любой точки мира.** Поднимите сервер на дешёвом VPS и поставьте перед
ним [Caddy](https://caddyserver.com) — он сам получит бесплатный сертификат:

```
chat.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

**Вариант В — временный туннель** (`cloudflared tunnel --url http://localhost:8080`,
`ngrok http 8080`): даёт https-ссылку, пока запущен туннель.

## 4. Что умеет мессенджер

Оформление — как в Bitrix24: слева список чатов, в центре лента с «пузырями» сообщений,
справа панель комментариев. Аватары круглые, у каждого — значок присутствия.

### Чаты

| Возможность | Где и как |
|---|---|
| **Свои групповые чаты** | кнопка **«＋ Новый чат»** слева: название + галочки, кого позвать. Создать может **любой** участник, сколько угодно чатов |
| **Добавить людей позже** | значок 👥 в шапке чата → «добавить». Новый участник получает ключ и видит всю прошлую переписку этого чата |
| **Личные сообщения** | в колонке слева раздел «Написать лично» — просто нажмите на имя. Переписку не видит никто, кроме вас двоих |
| **Кто в чате** | 👥 в шапке: список участников, кто сейчас онлайн; создатель может убрать участника |
| **Покинуть чат / переименовать / архивировать** | меню **⋯** в шапке чата |

### Сообщения

| Возможность | Где и как |
|---|---|
| **Комментарии внутри сообщения** | наведите на сообщение → 💬. Ветка открывается справа — «чат внутри чата» |
| **Ответ-ссылка на любое сообщение** | наведите → **↩**. Над полем ввода появится, на что отвечаете; в чате такое сообщение идёт **новым сообщением ниже** с плашкой-ссылкой. **Нажмите на плашку — и вас перенесёт к исходному сообщению** (оно подсветится) |
| **Кто прочитал** | под своим сообщением: ✓ отправлено, ✓✓ + кружки-аватары прочитавших (наведите — имена) |
| **Непрочитанные** | красные счётчики у чатов слева, число в заголовке вкладки браузера, красная точка на ветке комментариев |
| **Обращение через @** | наберите `@` и начало имени — появится подсказка (только участники этого чата). Упомянутый увидит сообщение подсвеченным, а у чата — оранжевый значок `@N` |
| **Картинки** | скрепка 📎 (в чате, в ветке и в личных) |
| **Удаление** | своё сообщение — любой; любое в своём чате — его создатель |
| **Поиск** | поле вверху ищет сразу **по всем вашим чатам**; у результата написано, где найдено; клик — переход к сообщению |

### Профиль и общее

| Возможность | Где |
|---|---|
| Смена своего имени и пароля | «Профиль» слева внизу |
| Круглый аватар | «Профиль» → «Загрузить аватар» |
| Шкала памяти сервера | слева внизу: проценты, мегабайты, размер текущего чата |
| Архивы | кнопка «Архивы» слева и меню ⋯ в чате |
| Управление людьми | «Управление» (у администратора): участники мессенджера, права, кодовая фраза |

Администратор мессенджера управляет людьми и кодовой фразой; внутри каждого чата главный — тот,
кто его создал.

## 5. Память и архивы

* Лимит по умолчанию — **25 МБ** на всю переписку (это десятки тысяч текстовых сообщений;
  картинки «съедают» больше). Шкала слева внизу показывает, сколько занято, и размер открытого чата.
* На 80 % появляется предупреждение; при переполнении новые сообщения не отправляются,
  пока какой-нибудь чат не заархивируют.
* **Каждый участник может сохранить архив себе** — меню **⋯** в чате → «Читаемая копия (HTML)»
  или JSON. HTML открывается в любом браузере без пароля, умеет искать по тексту, и ссылки
  между сообщениями в нём тоже работают. Кнопка «Архивы» слева выгружает сразу все ваши чаты.
* **Создатель чата** может нажать ⋯ → «Заархивировать на сервере и очистить чат»: копия ложится
  в хранилище (дома — в `alt-gentlemen/data/archives/`, в облаке — в базу), скачивается вам,
  а чат начинается с чистого листа. Участники и их ключи остаются. Скачать такой архив может
  любой, кто состоит в этом чате.
* Изменить лимит:

```bash
STORAGE_LIMIT=104857600 node server.js   # 100 МБ
PORT=9000 node server.js                 # другой порт
```

В облаке то же самое задаётся переменной окружения функции `STORAGE_LIMIT`.

## 6. Безопасность

* Сообщения, названия чатов, комментарии, вложения и аватары шифруются **в браузере**
  (AES-256-GCM). На сервер попадают только зашифрованные блобы — ни в файле
  `data/db.json`, ни в облачной базе нельзя прочитать ни переписку, ни даже названия чатов.
* **У каждого чата свой случайный ключ.** Он никогда не передаётся открыто: каждому участнику
  его «заворачивают» в ключ пары (ECDH P-256), который вычисляется прямо в браузерах двоих.
  Поэтому участники одного чата физически не могут прочитать другой, а сервер — ни один из них.
* **Личная переписка** шифруется ключом пары двоих. Ни сервер, ни другие участники,
  ни администратор её не прочитают, и сервер вообще не отдаёт такие сообщения посторонним.
* Пароли на сервер не отправляются: из пароля в браузере выводится отдельное проверочное
  значение (PBKDF2-SHA256, 150 000 итераций), сервер хранит только его scrypt-хеш.
* Подбор паролей и кодовой фразы ограничен: 25 попыток за 10 минут с одного адреса.
* Смена пароля перешифровывает ваши ключи и закрывает сессии на других устройствах.
* **Пароль восстановить невозможно.** Если друг забыл пароль: «Управление» → исключить его →
  он регистрируется заново по кодовой фразе. Его нужно будет заново позвать в чаты
  (прежние сообщения он увидит, как только получит ключ чата).
* Резервная копия: дома — скопируйте папку `alt-gentlemen/data`; в облаке — кнопка «Архивы» →
  «Выгрузить всё».

## 7. Чтобы мессенджер работал постоянно

Самый простой способ — [облако](#2-как-поселить-мессенджер-в-облаке-yandex-cloud). Если же
сервер домашний:

**Linux (systemd), файл `/etc/systemd/system/altg.service`:**

```ini
[Unit]
Description=Alt-Dzhentelmeny chat
After=network.target

[Service]
WorkingDirectory=/home/user/Marty/alt-gentlemen
ExecStart=/usr/bin/node server.js
Environment=PORT=8080
Restart=always
User=user

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now altg
```

**Проще:** `npm i -g pm2 && pm2 start server.js --name altg && pm2 save`.

## 8. Проверка работоспособности

Полный прогон — без всякого облака, все хранилища проверяются на месте:

```bash
node test/run-all.mjs        # 201 проверка в трёх режимах
node test/test-cluster.mjs   # 31 проверка: два экземпляра функции над одной базой
```

`run-all.mjs` трижды поднимает мессенджер и гоняет по нему один и тот же сценарий:
на файлах, на облачной базе (её роль играет заглушка `test/mock-ydb.mjs`, которая
по-настоящему проверяет подпись запросов) и целиком внутри облачной функции —
с событием Yandex Cloud Functions и адресом с приставкой.

Сценарий создаёт администратора и трёх участников и проверяет: создание групповых чатов
разными людьми, изоляцию ключей (чужой чат не читается), комментарии, ответы-ссылки, личные
переписки, отметки о прочтении, присутствие, обращения через @, добавление и исключение
участников, права, отдельную выдачу аватаров, личные архивы, архивацию с очисткой,
смену пароля и кодовую фразу.

`test-cluster.mjs` проверяет самое неприятное, что бывает в облаке: два экземпляра функции
работают над одной базой одновременно. Сообщения с обоих не теряются и не затирают друг друга,
длинные сообщения и аватары режутся на куски и собираются обратно, удаления и архивация
видны обоим, сессия, выданная одним, работает у другого.

Отдельно только API и шифрование (при запущенном сервере, на пустой базе):

```bash
node test-flow.mjs
```

```
alt-gentlemen/
├── server.js            запуск на своём компьютере
├── index.js             точка входа для облачной функции
├── lib/
│   ├── api.js           вся логика мессенджера (не знает, где лежат данные)
│   ├── model.js         структура базы и перенос старых версий
│   ├── store-file.js    хранение в файлах
│   ├── store-ydb.js     хранение в Yandex Database
│   ├── ydb.js           клиент Document API (подпись запросов, без библиотек)
│   └── static.js        отдача страницы
├── cloud/
│   ├── index.js         обработчик события Yandex Cloud Functions
│   ├── deploy.sh        развёртывание одной командой
│   └── api-gateway.yaml необязательный красивый адрес
├── public/
│   ├── index.html       экраны: настройка, вход, чат
│   ├── styles.css       оформление
│   └── app.js           клиент: шифрование, чаты, ветки, ответы-ссылки, поиск, архивы
├── test/
│   ├── run-all.mjs      прогон во всех трёх режимах
│   ├── test-cluster.mjs два экземпляра над одной базой
│   └── mock-ydb.mjs     заглушка Document API
├── test-flow.mjs        сценарий проверки API и шифрования
└── data/                база и архивы домашнего запуска (в Git не попадает)
```
