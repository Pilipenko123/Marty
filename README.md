# Marty.

## 🎲 Игральный кубик

Одностраничное приложение на чистом HTML + CSS + JS (без сборки и зависимостей): настоящая
3D-игральная кость с анимацией броска.

**Файл:** [`index.html`](index.html) — весь код (разметка, стили, скрипт) в одном файле.

### Как запустить

Просто открыть `index.html` в браузере двойным кликом — или через локальный сервер:

```bash
python3 -m http.server 8000     # затем открыть http://localhost:8000
```

### Что умеет

- **3D-кость на CSS-трансформах** — куб из шести граней, `perspective` + `preserve-3d`.
- **Анимация броска**: кость вылетает «из руки», крутится волчком (несколько полных оборотов),
  дважды подпрыгивает, приседает при посадке и слегка заваливается, как настоящая.
- **1–6 кубиков** одновременно, с пошаговым «броском друг за другом».
- **Закрепление кубика** (клик по кости, как в ятсе/покере) — закреплённые не перебрасываются.
- **Три дизайна** кости: слоновая кость, обсидиан, рубин.
- **Звук** удара о сукно и фанфарика на удачный бросок — синтезируются через WebAudio, файлов нет.
- **Сумма с анимацией счётчика**, метки «Дубль 6·6!», «Максимум!», «Семь — удача!».
- **История** последних бросков и **статистика**: число бросков, среднее, максимум и
  гистограмма частоты граней 1–6. Всё сохраняется в `localStorage`.
- **Управление с клавиатуры**: `Пробел`/`Enter` — бросок, `↑`/`↓` и `1`…`6` — число кубиков.
- Адаптивная вёрстка и поддержка `prefers-reduced-motion`.

### Как это работает

Номинал грани задаётся поворотом куба: `front=1, back=6, right=3, left=4, top=5, bottom=2`
(противоположные грани в сумме дают 7). Чтобы показать нужную цифру, достаточно выставить
переменные `--rx/--ry/--rz` в `rotateZ() rotateX() rotateY()` — длинный `transition`
превращает этот поворот в «волчок» (таблица `FACE_ROT` в скрипте).

Ключевая деталь — `spinTo()`: целевой угол всегда на ≥ 2 полных оборота дальше текущего,
иначе при повторении того же числа кость стояла бы на месте. Лишние обороты периодически
нормализуются (`currentAngles()`) — на ориентацию это не влияет, зато углы не расходятся
в десятки тысяч градусов.

Случайные числа берутся из `crypto.getRandomValues` с отбрасыванием остатка
(rejection sampling), поэтому распределение равномерное.
